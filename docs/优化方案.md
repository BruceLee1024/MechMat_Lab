## 1. 升级目标

把现有材料力学可视化实验室升级为可以保存、复现、对比和解释实验的学习工作台。

“更高级”落实到三件事：计算有依据，实验能积累，分析能深入。继续采用 React、TypeScript、Vite 和现有中文内容，以增量方式改进已有模块。

主要用户与需求：

| 用户 | 典型需求 | 升级后的体验 |
| --- | --- | --- |
| 学生 | 理解参数变化对结果的影响 | 从例题出发，修改参数、查看推导、比较工况 |
| 教师 | 演示、复现实验和布置练习 | 保存实验，导入课堂案例，导出带参数和图表的记录 |
| 有力学基础的用户 | 快速分析和检查结果 | 明确单位、模型假设、极值位置和计算适用范围 |

核心流程：**选择例题 → 设置材料、截面和载荷 → 查看结果及推导 → 保存工况 → 对比或扫描参数 → 导出实验记录。**

## 2. 现状与依据

以下保留开发前的代码与命令基线。开发后的变更、桌面/手机浏览器验证及剩余范围见 [首批开发记录](./首批开发记录.md) 和 [第二批开发记录](./第二批开发记录.md)。

| 现状 | 代码或验证依据 | 对升级的影响 |
| --- | --- | --- |
| 生产构建通过，但类型检查失败 | `npm run build` 通过；`tsc --noEmit` 报 8 处错误 | 构建成功不能替代正确性检查，需要先建立质量基线 |
| 多个求解器的结果结构不同步 | `AdvancedSolver.ts`、`ClassicSolver.ts`、`SolverEngine.ts` 缺少 `ElementResult` 字段；`DiagramPanel.tsx` 使用未声明的 `deflectionCurve` | 需要确认实际调用关系，统一结果契约，再扩展结果视图 |
| 数值输入规则过于统一 | `components.tsx` 的 `SliderInputControl` 只提交 `num > 0` 的值 | 合法的零载荷、端点位置和负方向参数可能无法通过输入框设置 |
| 实验状态未形成持久化工作区 | `index.tsx` 从 `DEFAULT_STATE` 初始化；求解器和截面模块另有本地状态 | 刷新或模块卸载后难以恢复实验，需要统一存档契约 |
| 实验主布局始终横向分栏 | `index.tsx` 的实验区域使用百分比宽度和鼠标拖拽 | 小屏设备需要独立的布局与触控操作方式 |
| 已有材料库和多种截面 | `components.tsx` 有材料选择器、截面选择器；`SectionModule.tsx` 支持自定义绘制 | 应扩展现有能力，重点解决跨模块复用与参数一致性 |
| 部分分析能力仍是简化模型 | 弯曲模块绘制近似变形；压杆模块固定计算长度系数为 1；应力模块实际使用平面应力参数 | 可以逐步增加真实曲线、边界条件和三维应力分析 |
| AI 已支持多模型与流式输出，但解析不保留跨块残片 | `ai.tsx` 对每次读取的数据执行 `chunk.split('\n')`，解析失败后忽略 | SSE 消息跨网络数据块时可能丢失内容，需要先修复传输可靠性 |
| PDF 工具未接入界面且依赖未声明 | `utils/exportPdf.ts` 导入 `html2canvas`、`jspdf`，清单中不存在；未发现调用处 | 先明确报告格式，再完善已有导出工具 |
| 首次加载仍有优化空间 | 当前构建主 JS 为 954.57 kB，gzip 为 247.77 kB；Tailwind 由 CDN 脚本加载 | 按模块拆包，迁移构建期样式，分别测量入口与异步资源 |
| 首页动画有资源清理问题 | `HomeModule.tsx` 匿名注册 resize 监听而未对应移除，粒子连线为双重遍历 | 需要处理重复挂载、低性能设备和减少动态效果偏好 |

以上不足并不证明所有公式或求解器均有错误。计算精度和单位一致性需要用解析案例逐项验证。

## 3. 四个阶段

### 阶段 A：计算与输入可靠性

对应任务：T01–T06，优先级 P0。

- 修复现有类型错误，明确当前实际使用的求解入口及结果结构。
- 建立单位转换工具。输入和展示保留 N/kN、mm/m、MPa/GPa 等习惯；内部计算统一为 N、mm、MPa、N·mm，并在边界转换。
- 为每类参数定义约束，区分正尺寸、允许为零的载荷、可带符号的应力及有限区间位置。暂时输入空值、负号或小数点时保留编辑状态，提交时再校验。
- 将公式计算从 React 视图提取为纯函数，返回结果、单位、模型假设和诊断信息。
- 对基础解析案例、无效输入、奇异结构建立回归验证。塑性曲线和超临界变形继续作为教学示意时，应在对应结果旁明确标识。
- 修复 AI 流式解析，加入停止、超时、重试和模块切换时的请求清理。

阶段完成标准：类型检查和生产构建通过；关键解析案例通过；无效输入不会进入求解；跨块 AI 回复不会丢字。

### 阶段 B：实验工作台

对应任务：T07–T11，优先级 P1。第一轮用户可见升级集中在这一阶段。

- 桌面提供可调整的实验/辅助面板与专注视图；手机通过“实验 / 理论 / AI”切换，实验图与参数保持可读。
- 建立有版本号的实验文档，保存材料、截面、载荷和模块参数。模型状态与界面状态分开，恢复时重新计算结果。
- 自动恢复最近实验；支持命名存档、另存为、删除、重置当前模块、撤销和重做。连续拖动一次记为一次操作。
- 接入典型例题和工况对比。首批支持拉伸、弯曲、扭转、压杆稳定，最多比较 4 个相同模块的工况。
- 结果呈现统一为关键指标、单位、极值位置、变化量、推导和模型说明；参考值为零时不显示无意义的百分比。
- 导出 JSON 用于复现，CSV 用于比较数据，PDF 用于实验记录。报告包含输入、公式、结果、图表、时间及计算版本。

示例：保存同一根简支梁的两个工况，仅改变矩形截面高度，对比最大应力和挠度，并查看惯性矩随高度三次方变化的解释。

阶段完成标准：完成“例题 → 修改 → 保存 → 刷新恢复 → 工况对比 → 导出 → 导入复现”的完整流程，桌面和手机均可操作。

### 阶段 C：高级分析与求解器

对应任务：T12–T17，优先级 P2。

| 模块 | 提升内容 | 计算与呈现要求 |
| --- | --- | --- |
| 平面弯曲 | 绘制挠度、剪力和弯矩曲线；点选任意位置；增加单参数扫描 | 区分载荷点挠度与真正最大挠度；极值及位置由计算得到 |
| 压杆稳定 | 两端铰支、两端固定、固定自由、固定铰支边界；计算长度系数 | 通过 μ 影响临界载荷，展示欧拉公式的弹性适用范围 |
| 应力状态 | 平面与三维模式；三主应力、von Mises、Tresca 和主方向 | 使用对称应力张量；重复特征值时说明主方向不唯一 |
| 截面计算 | 将现有材料、预设截面、自定义截面保存为可复用资源 | 分开定义几何属性、可用计算能力和近似公式，避免套用不适用的公式 |
| 结构求解器 | 网格吸附、坐标精确编辑、模型存档、撤销和模板 | 删除节点时处理关联单元与载荷；结果随模型版本更新 |
| 求解诊断 | 无约束、断开、重复/零长度单元、无效材料、奇异矩阵提示 | 标明问题位置；引入平衡残差检查；耗时求解按测量结果迁移到 Worker |

参数扫描首先只做单变量：选择范围和采样数，生成曲线，标注当前值和临界点。只有结果有效时才进行工况比较。

阶段完成标准：每项高级能力都对应独立解析或数值参考案例，不以“图看起来正常”作为正确性验收。

### 阶段 D：AI、性能和发布质量

对应任务：T18–T21，优先级 P3。

- AI 使用经过本地计算的参数、单位、结果和模型假设，提供“解释结果 / 比较工况 / 下一步实验”入口。数值结论以本地求解结果为依据。
- 按模块保存对话；API 凭据不进入实验存档、分享文件和导出报告。复用现有用户自备 Key 模式；服务端统一托管凭据作为后续可选方向。
- 首页加入继续上次实验、例题入口和可搜索的模块导航。学习记录区分“访问过”“保存过”“练习完成”，避免把访问次数当掌握程度。
- 懒加载重型模块和报告依赖；样式迁移到构建期，处理动态类名；KaTeX 样式与资源随构建交付；修复动画监听清理和减少动态效果模式。
- CI 增加类型、核心计算和关键交互检查；GitHub Pages 子路径和 Vercel 根路径都验证。先在开发分支整体验证，再形成可审查的发布改动。

性能目标：相同构建设置下，首页所需首批 JS gzip 总量争取降至 150 kB 以下；按真实设备采样记录拖动延迟，基础模块常见操作的第 95 百分位响应时间目标为 100 ms 以内。若达不到，保留测量结果与下一项优化，而不调整统计口径。

## 4. 技术设计

建议新增或逐步形成以下边界，不要求一次重构所有文件：

| 层 | 职责 | 建议位置 |
| --- | --- | --- |
| 计算层 | 单位、公式、截面属性、求解及诊断 | `mechanics/`，复用并梳理 `solver/` |
| 实验数据层 | 文档版本、模块参数、存档、迁移和撤销历史 | `experiments/`、`hooks/` |
| 交互组件层 | 数值输入、指标卡、实验工具栏和对比视图 | 从 `components.tsx` 逐步提取到 `components/` |
| 模块层 | 编排输入、计算结果和可视化 | 现有 `modules/` 与 `solver/SolverModule.tsx` |
| AI 层 | SSE 解析、请求生命周期、上下文和对话 | 从 `ai.tsx` 逐步提取到 `services/ai/` |
| 导出层 | JSON/CSV 序列化及 PDF 报告 | `utils/` 或 `reports/`，重型依赖按需加载 |

实验文档建议包含 `schemaVersion`、ID、名称、模块类型、材料、截面、载荷/参数、创建和更新时间。求解器使用独立的节点/单元/荷载结构；截面绘图保存路径及单位。不要把整个 React 状态直接序列化。

第一版存储使用本地浏览器存储与文件导入导出。数据量较大时再迁移 IndexedDB。云端账号、跨设备同步、多人协作、收费流程和全新三维渲染引擎不纳入本轮交付。

现有激活范围作为功能验收的边界：新工具遵循所在模块的可用性，分别检查未激活与已激活状态。

## 5. 验收方法

- **解析验证：** 独立公式给出参考值；一般双精度案例采用相对误差 ≤ 10⁻⁶，零值使用对应单位的绝对误差。离散求解按案例精度单独设阈值，不能用粗采样曲线替代精确极值验证。
- **示例案例：** 简支梁跨中集中力的支反力、最大弯矩与挠度；悬臂梁端部集中力；圆轴扭转；铰支压杆；纯剪切应力主值；矩形、圆形、空心圆截面属性。
- **无效输入：** 零长度、负面积、内半径不小于外半径、荷载越界、非有限数、损坏存档、断开模型和约束不足。
- **浏览器流程：** 例题、参数输入、重置、撤销、保存恢复、比较、导入导出、手机导航和 AI 停止重试。
- **响应式验证：** 至少覆盖 1440×900、1024×768、390×844；检查横向溢出、文字裁切、触控命中和滚动区域。
- **发布验证：** 使用干净依赖安装，运行类型检查、计算回归、关键浏览器验证和构建；检查两种部署路径的资源和动态模块加载。
